# TetoTV native playback source build

`build_native_playback.sh` creates every open-source native playback input used
by the Android application. Release builds consume these outputs directly and
have no fallback to the media-kit GitHub release JARs or libtorrent4j Maven JNI
JARs.

## Supported build host

Run the script on Linux x86-64. Windows contributors can use WSL2. The script
requires Git, curl, unzip, tar, CMake, Meson, Ninja, Autotools, pkg-config,
NASM, Make, a JDK 17 `java`/`javac`/`jar`, and `jq`.

```bash
./tool/native/build_native_playback.sh
```

The default output directory is `build/native-playback/outputs`. Set
`TETOTV_NATIVE_WORK_DIR` and `TETOTV_NATIVE_DOWNLOAD_DIR` to keep the large
working trees and verified downloads outside the repository. The download
archives are accepted only after both their exact byte length and SHA-256
digest match this script.

If a component completed before a later component failed, rerun with
`TETOTV_NATIVE_SKIP_LIBMPV=1` or `TETOTV_NATIVE_SKIP_LIBTORRENT4J=1`. A skip is
accepted only when all expected prior output JARs are present.

## Outputs

- `default-arm64-v8a.jar`
- `default-armeabi-v7a.jar`
- `libtorrent4j-2.1.0-38.jar`
- `libtorrent4j-android-arm-2.1.0-38.jar`
- `libtorrent4j-android-arm64-2.1.0-38.jar`
- `SHA256SUMS`
- `NATIVE_BUILD_PROVENANCE.json`

The two default JARs contain self-built `libmpv.so` and
`libmediakitandroidhelper.so`. The Android libtorrent JARs contain self-built
`libtorrent4j.so`; the core JAR contains the wrapper compiled from the pinned
Java source. The current set is identified as `2.1.0-38-tetotv.2` in the
release manifest while retaining upstream-compatible JAR file names. JAR entry
times and source-build environment values are fixed where practical. Both ARM
libtorrent outputs use 16 KiB-compatible ELF LOAD alignment. The build adds the
required maximum/common page-size linker options only for ARMv7 because NDK
r28 already produces compliant ARM64 segments.

## Source and toolchain policy

All Git inputs are immutable commit IDs. The Android NDK, Boost, and OpenSSL
archives are pinned by HTTPS URL, exact size, and SHA-256. The three patches
selected by the media-kit default flavor are also SHA-256 checked before they
are applied. The libtorrent API-24 compatibility edit is permitted only when
the NDK header matches the known pre-edit digest and must produce the known
post-edit digest.

The versioned native source ZIP generated by
`tool/release/verify_native_redistribution.ps1 -StageBundle` includes the exact
source snapshots, build script, notices, licenses, and provenance manifest.
It also includes `try_signal`, which is a separately pinned libtorrent gitlink
that ordinary `git archive` exports otherwise omit.

This process creates new TetoTV source-built artifacts. It does not claim that
their bytes reproduce the older upstream prebuilt JARs. Until a different
qualified person completes and signs the native-license review, releases must
remain explicitly unreviewed Betas and must not claim independent legal
approval.
