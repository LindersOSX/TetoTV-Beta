TetoTV self-built direct-torrent native component notice
========================================================

The optional Android direct-torrent engine is compiled by TetoTV from these
immutable sources; release builds do not resolve the upstream prebuilt
libtorrent4j Maven JNI JARs:

- libtorrent4j 09ffd391d4ef12e668cc032bffcbab47d9e2d5cb (MIT)
- libtorrent-rasterbar a01469c8d1f88dd83bed458ffccffab2727b9d2a
  (BSD-3-Clause and the additional notices in its full LICENSE file)
- try_signal 105cce59972f925a33aa6b1c3109e4cd3caf583d (BSD-3-Clause)
- libtorrent's bundled Ed25519 implementation (the public-domain/permissive
  notice shipped as LIBTORRENT_ED25519_LICENSE.txt)
- libdatachannel 6ab310b5887eab78cf0c0767a8ced2ebff8c7479 (MPL-2.0)
- libjuice 2de35247f0b15fa385406f3e2020d0e3d4d5cfcc (MPL-2.0)
- usrsctp ebb18adac6501bad4501b1f6dccb67a1c85cc299 (BSD-style)
- plog e21baecd4753f14da64ede979c5a19302618b752 (MIT)
- Boost 1.89.0 (Boost Software License 1.0)
- OpenSSL 3.5.2 (Apache-2.0)

This build uses WebTorrent with RTC_ENABLE_MEDIA=0. libsrtp and the media-only
nested sources are therefore not linked into libtorrent4j.so. They must not be
described as shipped binary components merely because their gitlinks exist in
the upstream recursive source graph.

Android NDK r28c runtime/toolchain notices are included because libc++ and
compiler runtime portions can be statically incorporated. Exact source
snapshots, source archive hashes, build instructions, and output hashes are in
the release's native playback source ZIP and
tool/release/native_playback_manifest.json. MPL-covered source snapshots and
any TetoTV modifications remain available in that ZIP.
